# S3 — 자동 채움·주기 출력 (보류)

이 문서는 `kc`의 TOTP 확장 중 **S3**(코드를 화면에 계속 띄우거나 다른 앱에 자동으로
채워 넣는 기능)를 왜 지금 만들지 않는지, 어떤 조건이면 다시 볼지 기록한다. 구현된 것은
**S2**(`kc otp`, `cp --otp`, `exec --otp`)까지다 — [일회용 코드 가이드](../guides/one-time-codes.md).

## 범위 후보

| 후보 | 내용 | 화면 노출 |
|---|---|---|
| `kc otp NAME --watch` | 남은 초와 함께 코드를 계속 다시 그린다 | 상시 |
| `kc otp --qr` | seed를 QR로 다시 표시(다른 기기에 등록) | seed 자체 |
| 브라우저·데스크톱 자동 채움 | macOS AutoFill 연동, 키보드 이벤트 주입 | 앱 내부 |
| Apple Passwords 자동 동기화 | iCloud 상태를 감시해 seed 갱신 | 없음 |

## 보류 이유

1. **화면·로그 노출면이 커진다.** S2는 코드가 클립보드나 자식 env로 한 번만 간다.
   `--watch`는 30초마다 코드를 다시 그리므로 화면 녹화·페어링·원격 지원 세션에 계속
   노출된다. `kc otp`가 파이프 출력을 기본 거부하는 이유와 정면으로 충돌한다.
2. **자동 채움은 OS 권한을 요구한다.** macOS AutoFill/접근성 이벤트 주입은 TCC 승인과
   실기기 검증이 필요하고, Linux·VM에서 fake 테스트로 대체할 수 없다. 현재 검증 예산은
   합성 시드·Linux 통합까지다.
3. **2요소 붕괴를 더 밀어붙인다.** 자동 채움이 되면 사람이 코드를 읽고 옮길 일이 없어져
   "같은 머신에 비밀번호와 seed"가 기본 구성이 된다. S1(seed 백업만)을 권장 기본으로
   유지하려면 자동화는 opt-in이어야 하고, 그 opt-in 비용이 S3의 핵심이다.
4. **Apple Passwords가 이미 한다.** macOS·iOS에서는 Passwords 앱이 AutoFill로 코드를
   채운다. kc가 같은 일을 두 번째로 구현할 이득이 작다.

## 다시 볼 조건

- `kind=otp` 항목이 실제로 여러 개 쌓여 `cp --otp`가 병목이라는 증거가 생길 때
- macOS AutoFill/TCC 검증 예산이 확보되고, `native-acceptance` 기준으로 실기기 증거를
  남길 수 있을 때
- 시크릿 저장소와 2요소를 분리하는 설계(예: seed는 휴대폰, kc는 코드만 받는 위임)가
  먼저 정해질 때

## 만든다면 지킬 제약

- 기본 off. `--watch`는 명시 플래그 + TTY에서만. 파이프·리다이렉트는 거부.
- `--qr`는 seed를 stdout에 쓰지 않고 TTY에만 그리며, 종료 시 화면 지우기를 시도한다.
- 자동 채움은 별도 바이너리·권한으로 분리하고, kc 본체는 seed 읽기만 담당한다.
- `kc audit`에 `otp` 액션 이름만 남긴다(코드·seed 없음). 정책 deny는 seed 읽기 지점에서
  그대로 적용한다.
- 실기기 증거 없이 "자동 채움 동작"을 PASS로 표기하지 않는다.
